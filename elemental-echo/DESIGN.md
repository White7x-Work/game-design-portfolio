# 《元素回响》Elemental Echo — 设计文档

| 项目 | 内容 |
|---|---|
| 游戏名 | 元素回响（Elemental Echo） |
| 类型 | 单人卡牌构筑 Roguelike（Deckbuilder Roguelike） |
| 平台 | TapTap 小游戏 / H5 |
| 屏幕方向 | **竖屏**（Portrait，750×1334 设计基准） |
| 单局时长 | 12–18 分钟（3 个 Act） |
| 入口 | `code/index.html` |
| 核心主题 | 元素配合 —— 单卡强度不是重点，**组合反应**才是战斗解法 |
| 文档版本 | v1.0（设计阶段，尚未实现） |

---

## 1. 设计支柱

1. **组合优先于数值**：一张卡的价值取决于它和谁相邻打出。玩家变强的路径是"学会更多组合"，不是"抽到更大的数字"。
2. **每回合是一次小解谜**：3 点能量 + 5 张手牌，如何排序触发最多反应，是每回合 10 秒的决策核心。
3. **元素即构筑方向**：遗物、卡池、敌人弱点都围绕五种元素展开，一局之内允许玩家形成"我是火雷爆发流"或"我是水土控制流"的身份认同。

## 2. 核心玩法

### 2.1 元素系统

五种元素：**火 Fire、水 Water、风 Wind、雷 Thunder、土 Earth**。

每张卡牌带 1 个主元素（少数卡为双元素）。战斗中的元素交互有两类：

- **反应**：本回合内连续打出的两张卡元素**不同** → 触发元素反应（一次性强效果）
- **共鸣**：本回合内连续打出的两张卡元素**相同** → 触发元素共鸣（小幅强化）

两者互斥：一次出牌只会走反应或共鸣其中一条分支。

### 2.2 元素反应表（10 组）

无序配对共 10 组。其中「过载」对顺序敏感，其余按配对判定。

| 配对 | 反应名 | 效果（v1 数值） |
|---|---|---|
| 火 + 风 | 焚风 | 对全体敌人造成 5 伤害；附加 2 层灼烧（每回合 2 伤，持续 2 回合） |
| 火 + 土 | 熔岩 | 战场熔岩 3 回合：敌方回合开始时受 4 伤害 |
| 火 + 水 | 蒸汽 | 敌方护甲减半；致盲 1 回合（敌方命中 -30%） |
| 火 + 雷 | 过载 | 单体 18 爆发伤害，自身受 4 反噬（**顺序敏感**：雷→火 改为「静电场」，己方下次攻击 +50%） |
| 水 + 风 | 霜寒 | 冻结 1 回合（目标跳过行动）；全体 3 伤害 |
| 水 + 土 | 泥沼 | 目标迟缓 2 回合（造成的伤害 -30%） |
| 水 + 雷 | 感电 | 传导：对**所有**敌人造成 6 伤害 |
| 风 + 土 | 沙暴 | 敌方命中 -40%，每回合受 3 伤害，持续 3 回合 |
| 风 + 雷 | 暴风 | 3 段各 4 伤害（多段判定，对多段护盾有奇效） |
| 土 + 雷 | 磁暴 | 移除目标全部护甲；眩晕 1 回合 |

### 2.3 共鸣与元素爆发

同元素连续两张触发**共鸣**，同元素连续三张触发**元素爆发**（每场战斗每种元素最多 1 次）。

| 元素 | 共鸣（2 连） | 元素爆发（3 连） |
|---|---|---|
| 火 | 灼烧层数 +2 | 全体 15 伤害 + 灼烧 3 层 |
| 水 | 抽 1 张牌 | 全体治疗 8 + 清空自身负面 |
| 风 | 该卡效果额外结算 1 次 | 全体 3 段 6 伤害 |
| 雷 | 伤害 +50% | 单体 24 伤害 |
| 土 | 获得 6 护甲 | 获得 18 护甲（可溢出为下回合保留） |

### 2.4 战斗规则

| 项 | 规则 |
|---|---|
| 能量 | 每回合 3 点（遗物可提升），卡牌消耗 0–3 |
| 手牌 | 回合开始抽 5 张，上限 7 张，多余弃掉 |
| 牌堆 | 抽牌堆 / 弃牌堆；抽牌堆空则洗回弃牌堆 |
| 回合内反应上限 | **2 次**（防止无限连锁；UI 明确提示剩余次数） |
| 护甲 | 回合结束清零（除非遗物/卡牌另有说明） |
| 敌人意图 | 回合开始展示下回合意图（攻击/防御/特殊），玩家可见 |
| 失败条件 | 玩家 HP ≤ 0，本局结束 |
| 胜利条件 | 击败 Act 3 Boss |

**反应链示例**：手牌 `火花(火)` → `疾风斩(风)` → `静电(雷)`
- 打火花(火) → 打疾风斩(风)：触发**焚风**（全体 5 + 灼烧）
- 打静电(雷)：与风触发**暴风**（3 段 4 伤）

两次反应用完，本回合后续出牌不再触发反应，只结算卡面。

### 2.5 卡牌

**类型**：攻击 / 技能 / 能力（能力为持续光环，打出后留在场上）。
**稀有度**：普通（白）/ 稀有（蓝）/ 史诗（紫）/ 传说（橙）。

**初始卡组（10 张）**

| 卡牌 | 元素 | 费用 | 效果 |
|---|---|---|---|
| 火花 ×3 | 火 | 1 | 6 伤害 |
| 疾风斩 ×2 | 风 | 1 | 5 伤害，抽 1 张 |
| 静电 ×2 | 雷 | 1 | 7 伤害 |
| 水幕 ×1 | 水 | 1 | 5 护甲，抽 1 张 |
| 岩壁 ×1 | 土 | 2 | 10 护甲 |
| 元素汇聚 ×1 | — | 0 | 本回合下一张牌视为双元素（可同时触发两种反应判定） |

**卡池规模**（v1 目标）：45 张卡，五元素各 8 张 + 5 张通用/双元素。

### 2.6 遗物

遗物是构筑方向的关键，改变元素规则而非单纯加数值。v1 目标 30 个，以下为示例：

| 遗物 | 效果 |
|---|---|
| 共鸣大师 | 同元素 2 连即触发元素爆发 |
| 反应堆 | 回合内反应上限 +1 |
| 熔火之核 | 灼烧伤害 +2 |
| 静滞护符 | 每回合首次冻结不消耗反应次数 |
| 双色棱镜 | 每场战斗第一张打出的卡视为双元素 |
| 沉重岩心 | 护甲溢出部分保留 1 回合 |
| 雷云容器 | 感电改为 3 段 |
| 枯竭之泉 | 能量 -1，但手牌 +2 |
| 元素亲和 | 起始手牌必定包含 3 种不同元素 |
| 过载保险 | 反噬伤害减半 |
| 潮汐沙漏 | 控制类反应（冻结/眩晕）持续 +1 回合 |
| 沙之记忆 | 每击败一名敌人，抽 1 张牌 |

### 2.7 局外元进程（Meta）

- 解锁：新卡（进卡池）、新遗物、角色天赋
- 统计：最高层数、总击杀、元素使用偏好
- 存储：本地 `localStorage` + TapTap 云存档（见 §8）
- 设计原则：局外只提供**广度**（更多可选卡与遗物），不提供**强度**（不做永久数值成长），保持每局公平。

## 3. 单局流程

### 3.1 状态机

```
启动页 → 主菜单 → 角色选择 → 地图(Act 1) 
   → [战斗 | 精英 | 商店 | 事件 | 休息 | 宝箱] 循环
   → Act Boss → 结算页（进入下一 Act 或通关）
   → 通关结算 / 失败结算 → 主菜单
```

### 3.2 地图节点

每个 Act 12–15 个节点，**分支路线**（3–4 条并行路径，每层可横向选择）。

| 节点 | 图标语义 | 出现概率 | 内容 |
|---|---|---|---|
| 战斗 | 剑 | 45% | 1–3 个普通敌人，胜利后三选一卡牌 |
| 精英 | 骷髅 | 12% | 强化敌人，胜利后获得遗物 |
| 商店 | 钱袋 | 10% | 卖卡（随机 5 张）+ 卖遗物（2 个）+ 移除卡服务 |
| 事件 | 问号 | 13% | 2–3 选项的随机文本事件，收益与代价并存 |
| 休息 | 篝火 | 10% | 二选一：回复 30% HP / 移除 1 张卡 |
| 宝箱 | 箱子 | 8% | 直接获得遗物或金币 |
| Boss | 王冠 | 固定 | Act 末尾单节点 |

### 3.3 经济

- 初始金币 50
- 普通战斗 15–25，精英 40–60，事件 0–40
- 商店卡牌 45–90，遗物 120–180，移除卡牌 60（每次 +20）

### 3.4 胜负

- **失败**：HP 归零 → 失败结算（展示层数、击杀、本局构筑），可分享
- **通关**：击败 Act 3 Boss → 通关结算（分数 = 层数×1000 + 击杀×50 + 剩余 HP×10 + 金币×2），上传排行榜

## 4. 操作设计

竖屏单手可完成全部操作，**不依赖拖拽**（拖拽易误触），采用两步式点选。

| 操作 | 行为 |
|---|---|
| 点选卡牌 | 卡牌抬起并放大 1.15×，显示目标指示 / 若为无目标卡直接高亮"可释放" |
| 再点敌方区域 | 释放卡牌（单体卡需点目标，全体卡点任意处） |
| 再次点同一张卡 | 取消选择 |
| 长按卡牌 300ms | 弹出详情浮层（完整描述 + 元素标签 + 反应预览） |
| 结束回合 | 右下角按钮，需长按 200ms 防误触（有能量剩余时额外二次确认） |
| 查看牌堆 | 点击左下抽牌堆 / 右下弃牌堆图标，弹出列表 |
| 反应预览 | 选中手牌时，**高亮所有会触发反应的牌**并在上方浮出反应名 + 效果摘要 |
| 震动反馈 | 反应触发 `vibrateShort`，受击 `vibrateShort`，暴击/爆发 `vibrateLong`（见 §8） |

**反应预览是核心体验**：玩家不必记忆 10 组反应表，UI 必须在出牌前告诉他"这张牌接下去会触发什么"。

---

### 4.1 战斗反馈（敌人动作必须"看得见"）

早期版本敌人行动是瞬时的，玩家只能看到血量跳变，感知不到"谁做了什么"。现已改为**两阶段回放**：

1. 点结束回合 → 立刻进入 `敌方回合` 黑底横幅态，结束回合按钮变为"敌方行动中…"并禁用，手牌变暗
2. 620ms 后真正结算，引擎产出的**事件流**按 300ms 间隔逐条回放：
   - 攻击：该敌人卡片前后冲刺动画（`lunge`）+ 红色边框辉光 + 玩家血条上浮 `-8` 红字 + 屏幕抖动 + 受伤音效 + 震动
   - 落空：只播冲刺动画并记录"攻击落空"
   - 治疗 / 加护甲 / 施加灼烧 / 召唤 / 蓄力：分别在敌人身上浮出对应文字（`+8`、`+5 护甲`、`蓄力 30` 等）
   - 敌人被灼烧：浮出 `-3` 橙色数字
3. 所有动作同时写入**战斗日志行**（战斗界面中部常驻，如"泥沼蟾 攻击 — 你受到 6 伤害"）

引擎侧对应 `battle.events` 数组（`attack` / `miss` / `heal` / `buff` / `debuff` / `charge` / `summon` / `burnTick` / `playerHit`），UI 只负责按节奏消费，两者解耦。

### 4.2 牌堆查看

战斗界面底部左右两个按钮显示当前抽牌堆 / 弃牌堆张数，**点击弹出完整列表**：

- 卡牌按元素（火→水→风→雷→土→双元素）排序展示，便于判断后续可凑的反应
- 空牌堆显示"这里还是空的"
- 底部提示"抽牌堆用完时，弃牌堆会洗回抽牌堆"

### 4.3 元素教学

三种入口，覆盖"第一次玩"和"随时查"：

| 入口 | 时机 | 内容 |
|---|---|---|
| **新手教学**（2 步） | 首次进入战斗自动弹出，之后不再打扰 | 第 1 步：能量/手牌/结束回合/敌人意图；第 2 步：不同元素=反应、相同元素=共鸣、三连=爆发，以及提示条的作用 |
| 战斗内 `规则` 按钮 | 战斗中随时 | 完整面板：10 组反应表（元素彩色标注）+ 5 种共鸣 + 5 种爆发 + 每回合限制 |
| 标题页 `元素规则（必看）` | 开局前 | 同一份完整面板 |

教学完成标记写入元进程（`tutorialDone`），随本地与云存档同步。

### 4.4 菜单与存档

**全局菜单**：标题页、地图页、战斗页都有入口（地图与战斗在右上角「菜单」按钮）。

| 菜单项 | 行为 |
|---|---|
| 继续游戏 | 关闭菜单 |
| 元素规则 | 打开规则+词条面板 |
| 设置 | 进入设置页，返回时回到**打开前的那一屏**（不在战斗中丢失上下文） |
| 保存并回主界面 | 把当前单局写入本地存档后回标题页 |
| 放弃本局 | 二次确认后清空存档并回标题页 |

**单局存档**（`localStorage`，键 `elemental-echo:run`）：

- 每次**离开一个节点**（含战斗胜利、商店结算、休息、事件）自动保存
- 保存内容：层数、HP、金币、卡组（按卡牌 id）、遗物、击杀、复活标记、整张地图结构
- 标题页检测到存档时显示「继续冒险」，可跨会话接着玩
- 战斗**进行中**保存会回到进入该节点前的状态（菜单里有明确说明，避免玩家误以为战斗中操作被保存）
- 结算（通关/失败）后自动清档

### 4.5 状态词条

战斗中的状态图标（🔥灼烧 / 🌫致盲 / 💧虚弱 / ❄冻结 / 💫眩晕 / 🌪沙暴 / ↩反伤）都带 `title` 提示，鼠标悬停可看「持续几回合」。

完整词条表放在规则面板第五节，覆盖：灼烧、致盲、虚弱、冻结、眩晕、沙暴、护甲、反噬、蓄力、反伤、熔岩、共鸣、元素爆发 —— 共 13 条，每条一句人话解释。

### 4.6 卡牌图鉴（收集与解锁）

图鉴不是"一览表"，而是**收集进度**：

- **初始状态**：每张卡只显示**图案**（元素色边框 + 符号图案 + 费用 + 稀有度点），名称显示 `？？？`，效果文本为"尚未遇见"
- **解锁条件**：该卡牌在**战斗奖励、商店、牌组**中真实出现过 → 记录进元进程 `cardSeen`，图鉴永久解锁，显示名称与完整效果
- **不因看图鉴而解锁**（否则一次点开全解，失去意义）
- **进度显示**：标题 `卡牌图鉴 X/22`
- 解锁记录随元进程一起走本地 + 云存档，跨设备保留

> 为什么这么设计：卡池只有 22 张时，"全解锁"本身是短期目标；未知卡面的 `？？？` 能制造"这局会不会开出新卡"的期待，成本几乎为零。

## 5. 界面设计

### 5.1 屏幕清单

1. **启动页**：Logo、加载进度、TapTap 授权状态
2. **主菜单**：开始、排行榜、图鉴、设置
3. **角色选择**：3 个角色（火/雷倾向、水/土倾向、风倾向），显示起始卡组差异
4. **地图页**：纵向滚动路径图，顶部状态条（HP/金币/层数/卡组按钮）
5. **战斗页**（核心）
6. **卡组页 / 遗物页**：网格列表，支持按元素筛选
7. **商店页**
8. **事件页**：立绘 + 文本 + 选项
9. **休息页**：篝火动画 + 二选一
10. **结算页**：分数、亮点回顾（最大反应伤害）、排行榜入口、分享按钮
11. **设置页**：音效/音乐/震动开关、语言

### 5.2 战斗页布局（750×1334）

```
┌─────────────────────────────┐
│ 顶部状态条                    │  HP条 | 护甲 | 层数 | 遗物图标行
├─────────────────────────────┤
│ 敌方区（1–3 个敌人）           │  敌人立绘 + 意图图标 + HP/护甲
│                             │  受击时抖动
├─────────────────────────────┤
│ 反应提示条                    │  当前可触发的反应名 + 剩余反应次数
├─────────────────────────────┤
│ 玩家状态区                    │  HP条 | 能量球 3/3 | 状态图标
├─────────────────────────────┤
│ 手牌区                        │  最多 7 张，横向排列，超出自动缩放
│  [卡][卡][卡][卡][卡]         │  元素色边框
├─────────────────────────────┤
│ 抽牌堆 ◀        结束回合 ▶     │  底部功能条
└─────────────────────────────┘
```

**卡牌尺寸**：宽 118 × 高 168（设计像素），间距 6。7 张时缩放至 0.82。
**设计分辨率适配**：以 `750` 为宽度基准，用 `vw` + `clamp()`，并预留 `env(safe-area-inset-bottom)`。

### 5.3 视觉规范

**元素配色 token**

| 元素 | 主色 | 光效色 |
|---|---|---|
| 火 | `#FF5A36` | `#FFB347` |
| 水 | `#2E9BFF` | `#7FD4FF` |
| 风 | `#3FD3A0` | `#B6FFE0` |
| 雷 | `#FFC53D` | `#FFF08A` |
| 土 | `#B07A4A` | `#E0B98A` |

**基础色**：背景 `#0E1116`，面板 `#161B22`，分隔线 `rgba(255,255,255,0.08)`，正文 `#E6EDF3`，次要文字 `#8B949E`。

**整体风格**：暗色底 + 高饱和元素辉光，卡牌为玻璃质感（半透明 + 内发光 + 元素色描边），细节用粒子而非贴图，降低美术资源依赖。

**动效原则**
- 所有界面切换 220ms ease-out
- 卡牌打出：向上飞 260ms + 缩放，落点爆炸
- 反应触发：**0.35s 的短暂停顿 + 屏幕外发光**，这是"爽点"，必须给足停顿
- 禁止长于 0.8s 的不可跳过动画

## 6. 关卡设计

### 6.1 三个 Act

| Act | 主题 | 元素倾向 | 敌人 HP 区间 | 设计意图 |

## 8. 服务端能力规划（全部通过 TapTap Minigame MCP 完成）

> 原则：客户端**不安装任何 SDK**，`tap` 是运行时全局对象；所有服务端资源（排行榜、分享模板、广告位）都先通过 MCP 工具在服务端创建，客户端只引用返回的 ID。

### 8.1 能力清单

| 能力 | 用途 | 服务端准备（MCP） | 客户端 API |
|---|---|---|---|
| **排行榜** | 通关分数排行 / 最高层数排行 | `list_leaderboards` → 无则 `create_leaderboard` 拿 `leaderboard_id`；`publish_leaderboard` 发布 | `tap.getLeaderboardManager()` → `submitScores` / `openLeaderboard` |
| **云存档** | 元进程（解锁、统计、最高层数）跨设备同步 | 无需创建，直接使用 | `tap.getCloudSaveManager()` + `tap.getFileSystemManager()` + `tap.env.USER_DATA_PATH` |
| **分享** | 结算页分享本局构筑与层数 | `create_share_template`（内容 ≤21 字符，需审核通过 status=1） | `tap.showShareboard({ templateId })` |
| **广告** | 激励视频：①失败后复活 ②道具解锁（重抽/补给包） | 需先 `check_ads_status` 确认状态「已生效」并拿到 `space_id`；然后 `get_ad_integration_guide` 生成 AdManager | `tap.createRewardedVideoAd` / AdManager |
| **震动** | 反应/受击/爆发的触觉反馈 | 无需准备 | `tap.vibrateShort` / `tap.vibrateLong` |

### 8.2 云存档硬约束（已确认，必须遵守）

- 存档文件 ≤ **10MB**，封面 ≤ 512KB
- 上传频率 **每分钟最多 1 次**（错误码 400001）→ 设计上只在**离开战斗节点、Act 切换、结算**时同步，不做每步保存
- 存档名**不能含空格或中文**（错误码 400009）→ 固定使用 `meta_slot1`
- 存档数量有上限（400003）→ 单槽位策略，用 `updateArchive` 覆盖
- 不允许并发调用（400007）→ 加请求队列，同一时刻只发一个云存档请求

### 8.3 降级策略（重要）

H5 在浏览器里预览时 `tap` 不存在。所有 TapTap 调用必须包一层能力探测：

```js
const hasTap = typeof window.tap !== 'undefined';
```

- 无 `tap` → 排行榜/分享/广告/云存档全部走本地模拟（localStorage + toast 提示"当前环境不支持"）
- 有 `tap` → 走真实 API
- **震动同理**：无 `tap.vibrateShort` 时用 `navigator.vibrate` 兜底，再没有就静默跳过

游戏核心战斗必须**完全离线可玩**，服务端功能只是增强，不能成为阻塞。

### 8.5 广告位设计（激励视频）

只有两个广告位，都必须是**可选增强**，不看广告也能通关。

**广告位 A：复活**

| 项 | 规则 |
|---|---|
| 触发时机 | 本局 HP 归零、进入失败结算前 |
| 效果 | 以 50% 最大 HP 复活，清空负面状态，本场战斗敌人 HP 不变 |
| 限制 | 每局最多 1 次；每局结束后重置 |
| 拒绝后果 | 直接进入失败结算，不受任何惩罚 |
| UI | 全屏「你的元素尚未熄灭」弹窗，两个按钮：`观看广告复活` / `就此结束` |

**广告位 B：道具（补给）**

| 项 | 规则 |
|---|---|
| 触发时机 | 商店节点（补给包）与战斗中的手牌重抽 |
| 效果 | 商店：免费获得 1 个遗物或 1 张稀有卡；战斗：重抽整手牌 1 次 |
| 限制 | 商店每次访问限 1 次；战斗中每场战斗限 1 次 |
| 拒绝后果 | 按钮置灰或不显示，正常游玩不受影响 |

**公平性约束（重要）**

- 广告收益不得影响排行榜公平：复活后的分数要标记 `revived: true`，**是否上榜在实现时按你的运营策略决定**（本设计默认：仍可上榜，但结算页如实展示"本局使用过复活"）。
- 广告不可自动播放，必须玩家主动点击。
- 广告加载失败或超时（>5s）→ 直接放行奖励或静默降级，**不能让玩家卡住**。
- 无 `tap` 环境（浏览器预览）→ 广告按钮不显示。

## 9. 技术方案与目录结构

### 9.1 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | 无框架，原生 ES Module | 零构建、零依赖，TapTap 小游戏可直接托管静态文件 |
| 渲染 | DOM + CSS（卡牌/UI）+ 单 Canvas（粒子） | UI 交互简单，Canvas 只承担特效 |
| 状态 | 单一 `store.js`（不可变状态 + 事件订阅） | 战斗逻辑需可回放/可存档 |
| 存档 | `localStorage`（兜底）+ 云存档（增强） | 见 §8.3 |
| 适配 | `vw` + `clamp()` + 安全区 | 竖屏基准 750 |
| 资源 | SVG 图标 + CSS 渐变 + 程序化音效 | 尽可能少依赖二进制素材 |

### 9.2 目录结构

```
elemental-echo/
├── DESIGN.md              ← 本文档
├── ASSETS.md              ← 美术/音频素材需求清单
├── 元素回响.html           ← 【单文件版】双击即玩
├── dist/
│   └── index.html         ← 单文件版副本（用于上传 TapTap）
├── code/                  ← 模块源码
│   ├── index.html         ← 模块版入口（需 HTTP 服务）
│   ├── css/
│   │   └── style.css      ← 全部样式（变量/卡牌/各界面/动画）
│   ├── js/
│   │   ├── main.js        ← 启动、音频解锁、云存档引导
│   │   ├── ui.js          ← 全局状态 S + 全部界面与交互
│   │   ├── data.js        ← 元素/反应/共鸣/爆发/卡池/遗物/敌人/事件
│   │   ├── engine.js      ← 战斗引擎（纯逻辑，无 DOM）
│   │   ├── run.js         ← 单局流程（地图/奖励/商店/计分）
│   │   ├── fx.js          ← Canvas 粒子 + Web Audio 合成音效
│   │   └── tap.js         ← tap 能力探测与封装（排行榜/云存档/分享/广告/震动）
│   └── assets/            ← 预留（v1 无二进制素材依赖）
├── tools/
│   ├── serve.cjs          ← 本地预览服务器（仅模块版需要）
│   └── build.cjs          ← 打包器：模块 → 单文件 HTML
├── 启动预览.cmd            ← 双击启动本地预览（模块版）
└── assets/                ← 设计稿/临时素材（不参与运行）
```

> 实现说明：实际代码采用**按职责合并的 7 个模块**，而非上面早期规划的深层目录。原因是零构建、直接用浏览器原生 ES Module 加载，深层目录会增加路径复杂度而无收益。`data.js` 与 `engine.js` 完全无 DOM 依赖，因此可以被 Node 直接加载做自动化测试。

### 9.3 关键实现约束

- **两种运行形态**（均已构建）：
  - `元素回响.html` — **单文件版，双击即玩**。打包器把 7 个 ES Module + CSS 内联进一个 HTML，0 外部引用，因此不受 `file://` 的 CORS 限制。
  - `code/index.html` — 模块源码版，需 HTTP 服务（双击 `启动预览.cmd` → `http://127.0.0.1:8123/`）。ES Module 在 `file://` 下必被拦截，这是浏览器安全策略，不是配置问题。
- `dist/index.html` 为单文件版副本，目录形式便于后续 `upload_h5_game` 上传。
- 改动 `code/js/**` 后需重新执行 `node tools/build.cjs` 同步单文件版。
- 单局状态可序列化成一个 JSON（用于存档与调试回放）
- 战斗引擎必须与 UI 解耦：`engine.js` 纯逻辑推进，`ui.js` 只负责渲染与交互
