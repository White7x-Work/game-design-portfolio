- 文档日期：2026-10-27

## 1. 产品定义

### 1.1 目标体验

- **10 秒上手**：会玩贪吃蛇就会玩，不需要读长教程。
- **20～30 秒一次成长**：收服、升级、三选一持续给正反馈。
- **尾巴就是构筑**：身后每只动物都看得见、有名字、有能力，不是抽象数值。
- **死亡可归因**：输在贪长、贪分或操作失误，而不是随机刷怪糊脸。
- **单手可玩**：手机竖屏/横屏都能完成一局。

### 1.2 设计支柱

1. **看得见的成长**：动物实体挂在尾部，升级有星星、光效和 HUD 图鉴条。
2. **贪吃与风险的拉扯**：收得越多，被动越强，但身体越长、转向越危险。
3. **每局不同**：动物刷新、buff 稀有度、岩石布局共同制造局内差异。
4. **轻量但有手感**：厚描边卡通、挤压回弹、飘字、轻微震屏，不堆特效。

### 1.3 核心循环

```
移动 → 碰动物收服（+经验 / 被动升级 / 身体变长）
     → 吃浆果（+经验 / +分数）
     → 躲岩石、墙、自己
     → 升级 → 暂停三选一 buff
     → 难度上升 → 死亡 → 结算 → 再来一局
```

### 1.4 单局节奏（目标）

| 时间 | 体验目标 |
| --- | --- |
| 0:00～0:30 | 学会转向、收服 2～3 只动物，升到 Lv.2～3 |
| 0:30～2:00 | 尾巴成型，出现第一个稀有动物或 buff，岩石开始增多 |
| 2:00～5:00 | 身体明显变长，速度提升，护盾/复活开始救场 |
| 5:00+ | 高压贪分，玩家主动决定“再收一只”还是“保命” |

### 1.5 MVP 非目标（明确不做）

- 多地图、章节、Boss、关卡节点地图
- 主动技能按键、动物进化树、图鉴收集、成就系统
- 在线排行榜、账号、云存档
- 背景音乐（首版仅音效）、剧情、角色对话
- 多人联机、关卡编辑器

以上进入 backlog，不阻塞当前版本。

## 2. 玩法规则

### 2.1 棋盘与移动

- 逻辑棋盘固定 **20 × 20**，正方形；屏幕自适应留边，桌面和手机规则一致。
- 初始蛇长 **3 节**（头 + 2 节身体），初始向右。
- 基础 tick **150ms**；每 30 秒减少 3ms，最低 95ms。
- 兔子被动和“轻快步伐”对 tick 做乘法修正，最终 clamp 在 **70ms**。
- 输入队列最多缓存 **2 次转向**；禁止 180° 反向；快速“上→左”可在同一 tick 内生效。
- 逻辑按格走，渲染在上一格与当前格之间插值，保证顺滑但不改变判定。

### 2.2 收服规则

- 蛇头进入动物所在格 → 立即收服，身体 +1 节；动物优先填入蛇头后的第一个空节段，第一只头像紧贴蛇头，队尾补空节段。
- 收服获得 **4 经验**；该物种等级 +1（最高 5 级），并立即刷新该物种被动。
- 物种首次收服即激活被动；重复收服只升级该物种，不新增被动槽。
- 物种达到 5 级后再次收服：**不再增长身体**，改为 +4 经验、+15 分，避免无限长导致必死。
- 蛇身每个有动物的节段都绘制对应头像；HUD 显示已收服物种与等级。

### 2.3 拾取物与障碍

| 对象 | 数量上限 | 规则 |
| --- | --- | --- |
| 动物 | 场上 6 只 | 收服后 0.6～1.4s 在安全空地刷新 |
| 浆果 | 场上 4 颗 | +1 经验、+5 分；吃掉后 1～2s 刷新 |
| 金浆果 | 包含在浆果中 | 基础 8% 概率；+5 经验、+25 分；受“黄金时代”加成 |
| 岩石 | 最多 21 块 | 每 25s +1；撞到即死（护盾/尾刃/尖刺可解） |

**刷新安全规则（必须实现）**

- 不刷在蛇身、已有物体、岩石上。
- 不刷在蛇头当前朝向的前 3 格内。
- 动物不刷在距蛇头曼哈顿距离 4 格以内。
- 岩石不刷在距蛇身 2 格以内；连续 30 次找不到位置则跳过本次刷新。
- 当场上障碍 + 拾取物占用超过 55% 格子时，暂停新增岩石。

### 2.4 经验与升级

- 升级所需经验：`need = 5 + (level - 1) * 4`。
  - Lv.2 需 5，Lv.3 需 9，Lv.4 需 13……
- 每次升级暂停游戏，展示 **3 张 buff 卡**，玩家选择 1 张后继续。
- 稀有度解锁：
  - Lv.1～2：只出普通卡。
  - Lv.3 起：稀有卡权重 30。
  - Lv.6 起：史诗卡权重 8。
- 同一轮 3 张卡不重复；已满层的卡不再进入卡池。
- 卡池不足 3 张时，用保底卡“**小确幸**：+300 分”补位。
- 选择后立即重算派生属性；若 tick 变化，当前累积时间做 clamp，避免跳格。

### 2.5 难度曲线

- 每 30 秒：速度 -3ms（至 95ms 下限）。
- 每 25 秒：岩石 +1（至 21 块上限）。
- 存活 2 分钟后：动物刷新间隔缩短 10%，金浆果概率小幅上升。
- 不引入追踪型敌人；压力来自身体长度、岩石密度和速度。

### 2.6 死亡、护盾与复活

**致死来源**：撞墙、撞自己、撞岩石。

处理顺序（每个 tick）：

1. 消费一次转向输入。
2. 计算下一格。
3. 判墙 → 判岩石 → 判自身。
4. 若致死：
   - 有尖刺/尾刃冷却：摧毁岩石并继续移动（仅岩石）。
   - 有护盾：消耗 1 层，取消本 tick 移动，摧毁岩石（若为岩石），获得 1.2s 无敌。
   - 有复活次数：消耗 1 次，身体裁剪为 `max(3, floor(length * 0.7))`，清除周围 3 格危险物，获得 2s 无敌。
   - 否则游戏结束。
5. 无敌期间忽略墙/岩石/自身致死判定，但正常移动与拾取。

- 护盾来自乌龟被动，基础 1 层、45s 充能；乌龟 Lv.3 / Lv.5 各 +1 最大层数。
- “厚甲”buff 使充能时间 ×0.85/层，最低 15s。
- 复活来源：熊猫被动 + “额外生命”buff；总复活次数上限 **4**。
- 复活后若仍贴墙，2s 无敌足够转向脱困。

### 2.7 基础数值

| 项目 | 初始值 |
| --- | --- |
| 棋盘 | 20 × 20 |
| 初始长度 | 3 |
| 基础 tick | 150ms |
| 速度下限 | 95ms（修正后 70ms） |
| 初始动物 / 浆果 | 3 / 2 |
| 收服经验 / 分数 | 4 / 10 |
| 浆果经验 / 分数 | 1 / 5 |
| 金浆果经验 / 分数 | 5 / 25 |
| 生存分 | 1 分/秒 |
| 护盾充能 | 45s 起 |
| 复活无敌 | 2s |

计分与经验公式：

```
单次得分 = 基础分 × 狐狸加成 × 精打细算加成
单次经验 = 基础经验 × 狐狸加成
最终得分 = floor(累计得分 + 生存秒数)
```

## 4. 技术方案

### 4.1 形态与约束

- **一个 `index.html`**：内联 CSS + 内联 JS，无 CDN、无 fetch、无外部字体/图片。
- 目标：双击 `file://` 可玩；静态服务器下也正常。
- 代码保持 ES2020，单 IIFE，严格模式，顶部集中配置。
- 预计体量 2500～4000 行；超过 5000 行再评估拆分，但 v1 不引入构建。
- 目标文件体积 **< 250KB**。

### 4.2 目录结构

```
tail-zoo/
├─ index.html          # 唯一运行文件
├─ PLAN.md             # 本清单
├─ README.md           # 操作说明 / 玩法（M5）
├─ CHANGELOG.md        # 版本记录（M5）
└─ backups/            # 发布快照（M5）
```

### 4.3 单文件内部分区

```js
(() => {
  'use strict';

  // 01 CONFIG       棋盘、tick、经验、数量、调参常量
  // 02 DATA         ANIMALS、BUFFS、PALETTE、文案
  // 03 UTIL         clamp/lerp/easing/rng/roundRect/安全取格
  // 04 SAVE         localStorage 封装 + 内存兜底
  // 05 AUDIO        WebAudio 合成音效
  // 06 INPUT        键盘、滑动、方向键、输入队列
  // 07 SPRITES      动物/浆果/岩石离屏缓存
  // 08 ENTITIES     蛇、拾取物、岩石、粒子、飘字
  // 09 SYSTEMS      刷新、碰撞、经验、buff、难度、复活
  // 10 UI           DOM 屏幕状态机、HUD、卡片
  // 11 LOOP         固定逻辑步 + 插值渲染
  // 12 BOOT         启动、resize、可见性、debug 接口
})();
```

### 4.4 状态机

```
BOOT → TITLE → PLAYING ⇄ PAUSED
                 ├→ LEVELUP → PLAYING
                 └→ GAMEOVER → PLAYING / TITLE
```

- 只有 `PLAYING` 推进逻辑；`LEVELUP`、`PAUSED`、`GAMEOVER` 冻结计时。
- 屏幕切换统一走 `setScreen(next)`，负责 DOM 显隐、焦点、输入模式。

### 4.5 核心数据结构

```js
const state = {
  screen: 'title',
  time: 0, tickMs: 150, acc: 0,
  snake: [{ x, y, px, py, species }], // 0 = 头
  dir: { x: 1, y: 0 },
  turnQueue: [],
  species: { rabbit: 2, turtle: 1 },  // 物种等级
  buffs: { swift: 2, armor: 1 },      // 叠加层数
  shields: { current: 1, max: 1, cd: 0 },
  lives: 0,
  animals: [], berries: [], rocks: new Set(),
  particles: [], floats: [],
  stats: { captures: 0, berries: 0, startedAt: 0 }
};
```

- 所有派生属性（tick、拾取半径、得分倍率、护盾上限）由 `deriveStats()` 从 `species + buffs` 现算，**不直接改基础值**，避免读档/加卡后数值漂移。
- 蛇身用数组 + `Map("x,y" → index)` 做 O(1) 自撞查询；每 tick 重建，长度 < 200 时开销可忽略。

### 4.6 游戏循环

```js
let last = performance.now(), acc = 0;

function frame(now) {
  const dt = Math.min(now - last, 100);
  last = now;

  if (state.screen === 'playing') {
    acc += dt * worldSlowFactor();
    while (acc >= state.tickMs) {
      tick();
      acc -= state.tickMs;
      if (state.screen !== 'playing') break;
    }
  }

  render(state.screen === 'playing' ? acc / state.tickMs : 1);
  requestAnimationFrame(frame);
}
```

- 逻辑 tick 内完成移动、碰撞、拾取、计时、难度、升级判定。
- 渲染层用 `lerp(prev, curr, t)`；转向处用圆角连接线遮住缝隙。
- 页面隐藏时暂停并重置 `last`，避免回来跳帧。

### 4.7 输入

- 键盘：WASD / 方向键转向；`Space`/`P` 暂停；`1/2/3` 选卡；`R` 重开；`Esc` 返回。
- 触屏：在画布任意处滑动，阈值 24px 或 0.6 格；取主轴方向。
- 触摸设备默认显示半透明虚拟方向键（可在设置中关闭），保证精确操作。
- 输入统一进入 `turnQueue`：与队尾方向相同则忽略，反向则拒绝，最多 2 条。
- `touch-action: none`、禁止双击缩放、禁止长按菜单；UI 按钮阻止事件冒泡。

### 4.8 碰撞与 tick 顺序

```
1. 结算蛇头当前格拾取：动物 → 收服并 append；浆果 → 加经验/分
2. 取 turnQueue 第一条，合法则更新 dir
3. next = head + dir
4. 越界 → fatal(wall)，蛇头不移动
5. next 在 rocks → 尝试尖刺/尾刃/护盾；无保护时蛇头先进入岩石格再 fatal(rock)
6. next 在蛇身（含尾巴）→ 护盾/复活；无保护时蛇头先进入该格再 fatal(self)
7. 移动蛇身；更新 prev/curr
8. 更新护盾 CD、技能 CD、沙漏、难度计时
9. 结算经验；若升级 → setScreen('levelup')，本 tick 结束
10. 检查刷新、粒子生命周期
```

> 关键：拾取在 tick 开头结算，此时插值画面中的蛇头已到达当前格；致命碰撞仍先判定，但无保护时会先完成最后一步移动再结算，让死亡画面与判定点重合。护盾/复活触发时取消本 tick 移动。

### 4.9 刷新导演

- 独立计时器：岩石 25s、动物补位 0.6～1.4s、浆果 1～2s。
- `findFreeCell(opts)` 统一处理安全距离、占用、朝向禁区；失败即跳过。
- 刷新权重表集中配置，便于调平衡。
- 2 分钟后启用第二阶段参数（刷新间隔、金果概率）。

### 4.10 Debug 接口（必须预留）

`?debug=1` 时：

- 左上角显示 FPS、tick、长度、场上物体数、当前 buff。
- 快捷键：`G` 无敌、`L` 强制升级、`1～8` 刷动物、`B` 浆果、`K` 岩石、`+/-` 调速、`P` 暂停。
- 暴露 `window.__tailzoo`：`state`、`spawnAnimal(id)`、`spawnBerry()`、`forceLevelUp()`、`grantBuff(id)`、`die()`、`reset()`。
- 自动化冒烟测试只依赖该接口，不依赖像素坐标。

## 5. 美术与渲染规范

### 5.1 视觉方向

- **2D 卡通、厚描边、马卡龙草地、圆角几何**；无写实纹理。
- 描边色统一深墨蓝 `#2B2B3C`，线宽 2.5～3px（按格子缩放）。
- 动物占格 0.75～0.85，头略大；眼睛白底 + 高光，腮红两枚椭圆。
- 所有动物用 3～5 个主色，禁止细碎阴影；用大色块保证 28px 下可辨认。
- 动效：待机轻微上下浮动 + 2° 摆动；收服时挤压 0.85 → 1.15 → 1；升级时星星迸发。

### 5.2 色板

| 用途 | 色值 |
| --- | --- |
| 墨色描边 / 文字 | `#2B2B3C` |
| 纸张 / 卡面 | `#FFF8E7` |
| 草地 A / B | `#A8E6A3` / `#9ADB95` |
| 主橙 | `#FF9F45` |
| 粉红 | `#FF6B8A` |
| 金黄 | `#FFD166` |
| 天蓝 | `#7FD1F7` |
| 叶绿 | `#4CAF78` |
| 危险红 | `#EF476F` |

### 5.3 屏幕与 HUD

- 桌面：棋盘居中，左右留白放标题/收藏条；HUD 顶部横条。
- 手机竖屏：HUD 顶部两行（分数/最佳；等级/经验条），棋盘居中，收藏条在棋盘下方。
- 手机横屏：HUD 收进左侧窄栏，棋盘居中。
- HUD 元素：分数、最佳、等级 + 经验条、身体长度、护盾层数、物种图标条、暂停按钮。
- 收藏条：8 个物种小图标，未收服置灰，收服后显示等级小点（最多 5 点）。

### 5.4 场景与物件

- 草地：18×18 棋盘格，双色交错，极淡；边缘画一排小花/草簇。
- 岩石：圆角灰石 + 高光 + 两三条裂纹，明显区别于动物。
- 浆果：红色圆果 + 绿叶；金浆果加金色描边与闪光。
- 蛇身连接：0.62 格宽的圆角粗线，颜色随尾部渐变；动物精灵叠加其上。
- 头部：当前物种？不，蛇头固定为小蛇形象（绿色/奶油色），戴一撮呆毛；转向时眼睛看向前进方向。

### 5.5 粒子与镜头

- 收服：6～10 颗星星 + 1 个飘字。
- 升级：20～30 片彩纸，限制 400ms。
- 撞击：屏幕震动 6px / 180ms + 红色 vignette 闪一次。
- 护盾：六边形环破裂；复活：绿色光环扩散。
- `prefers-reduced-motion` 下关闭震屏、减少粒子、保留必要反馈。

### 5.6 性能约定

- 所有动物/物件按当前格尺寸预渲染到离屏 canvas（2x），运行时只 `drawImage` + 变换。
- 粒子池最多 220，飘字最多 12；超出复用最旧对象。
- DPR 上限 2；resize 防抖 150ms；静态草地缓存，不在每帧重画路径。
- 渲染循环内避免创建数组/对象；路径数组复用。
- 目标：中端手机 60fps；10 分钟单局内存稳定。

### 6.2 文案风格

- 轻松、短句、有一点动物梗；不使用生硬的系统提示。
- 示例：复活提示“熊猫把你拽了回来”；撞墙“尾巴打结了”；新纪录“全场动物起立鼓掌”。

- 使用 `dvh`/`dvw` 与 `safe-area-inset-*`；禁止页面滚动与缩放。
- 按钮最小 44×44px；卡牌整卡可点。
- 滑动优先，虚拟方向键为辅助；两者可同时存在，不冲突。
- 切后台自动暂停；回来停在暂停页，不直接续跑。
- 首次点击后解锁 AudioContext。

### 6.4 可访问性

- 卡牌稀有度同时用文字 + 颜色；对比度 ≥ 4.5:1。
- 键盘可完成开始、选卡、暂停、重开全流程；焦点环可见。
- 减少动态效果选项跟随系统，也可手动覆盖。
- 无闪烁超过 3Hz；音效可完全静音。
- `<noscript>` 提示需要开启 JavaScript。

| --- | --- |

### 7.2 存档

```js
// localStorage key: tailzoo.v1
{
  version: 1,
  bestScore: 0,
  runs: 0,
  muted: false,
  seenTutorial: false,
  shake: true,
  dpad: true
}
```

- 读写包 try/catch；不可用时退化为内存对象，游戏仍可玩。
- 只存元数据，不存局内进度；刷新即新开一局。
- 结算时更新最佳分与局数。

### 14.2 接入原则

1. **不装 SDK**：`tap` 由 TapTap 小游戏宿主注入，等价于 `window`，禁止 npm 安装任何包。
2. **单文件不变**：所有平台代码内联在 `index.html` 的 `00. TAPTAP PLATFORM` 段，上传只需一个 `index.html`。
3. **可降级**：`tap` 不存在时（普通浏览器 / `file://`）排行榜与广告全部静默降级，不抛错、不阻断游玩。
4. **ID 唯一来源**：排行榜 ID 用后台返回的客户端 ID 字符串（不是数据库数字 ID）；广告位 ID 只能来自 MCP `check_ads_status`，禁止手填或复用其他应用。
5. **不自动发布**：产物只做到"可上传"，不调用上传/发布/提审。

### 14.3 排行榜

- 时机：`die()` 结算时 `submitScore(finalScore)`；重复死亡时因为 `calc_type = best`，服务端只保留最高分。
- 入口：标题页 `排行榜` 按钮、结算页 `排行榜` 按钮 → `openLeaderboard({ collection: 'public' })`。
- 反馈：`#rankNote` 显示"本局 N 分已上传排行榜" / 失败原因；非客户端环境提示"排行榜需要在 TapTap 客户端内打开"。

### 14.4 激励视频复活

- 触发：结算页「看视频复活」按钮，每局上限 `CONFIG.adReviveLimit = 1`。
- 奖励：原地复活，保留分数，蛇身修剪到 50%，2 秒无敌，自动清除头部周围 3 格岩石，方向改为朝向棋盘中心的**安全格**（不与蛇身/岩石/边界重叠）。
- 就绪条件：`PLATFORM.adsReady = adsEnabled && adSpaceId && tap`；未就绪时按钮整块隐藏，避免出现点不动的假广告入口。
- 调试：`?admock=1` 模拟 1.2 秒激励视频，用于浏览器内验证完整链路。
- **实现**（v1.4.0）：启动时 `tap.createRewardedVideoAd({ adUnitId: PLATFORM.adSpaceId })` 预加载；`show()` 失败 → `load()` → 只重试一次；**超时只用于「拉起广告」阶段（15s）**，`show()` 成功后换 180s 长兜底，播放中由 `onClose` 发奖；`onClose` 兼容 `{isEnded:true}` / `true` / 无参数，明确 `isEnded:false` 才不发。
- **真机教训**：v1.3.0 从 `show()` 起算 15s 超时，而激励视频常播 15–30s，超时抢先清空发奖回调 → 看完广告不复活。v1.4.0 已修，并由 E2E「广告超过 15 秒仍正常发奖」锁死。
- **真机验证**：以上只验证了调用契约（headless + 假 `tap`），广告能否真正播放必须在 TapTap 客户端内实测。
